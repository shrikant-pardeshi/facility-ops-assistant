# Sample Data

All data is **fictional**. Building names, people, tenants and vendors are invented.
Equipment makes are used only to make the asset register realistic. Compliance
documents are **illustrative paraphrases, not legal text**.

The data is designed around **`AS_OF_DATE=2026-10-01`** (set in `.env`), so every
status below is reproducible whatever day the demo runs.

The SQLite database (`facility_ops.db`) is built from these files on first run
(`python scripts/init_db.py --reset` rebuilds it). Seed files stay the source of truth.
`pytest tests/test_seed_data.py` checks ID formats, uniqueness, foreign keys and KB front-matter;
`tests/test_knowledge_formats.py` checks the .txt / .docx / .pdf documents.

**Knowledge-base formats.** Documents can be Markdown (YAML front-matter), plain text (optional
`Title:` / `Tags:` / `Doc-Type:` header; `## ` or ALL-CAPS headings), Word (title and keywords from
document properties, Heading 2 = section) or PDF (title and keywords from PDF metadata, larger or bold
lines = headings). Without metadata, the doc ID comes from the file name (`SOP-XXX-001_...`) and the type
from the folder. The three non-Markdown samples are generated by `scripts/make_sample_docs.py`.

Asset, AMC and compliance questions (storylines 2–5, 10) need you to be signed in as
staff, such as `EMP-1024`. Signed in as an occupant like `OCC-2001`, they are refused with
an explanation (access option B). Occupants can raise complaints and check their own
tickets, in their own building only. Staff can switch to either facility; for FAC-002 try
"Is the AMC on lift B active?" or "Lift B door is not closing properly, raise a work order".
